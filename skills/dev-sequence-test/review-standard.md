# 测试验收验收规则

适用范围：本期已声明产物及其必要基线。保留项目特殊标准；不适用逐项说明理由。

| 检查ID | 验收标准 |
|---|---|
| TEST-00 | 最终测试在新会话独立设计并实际执行；具有本轮身份、TC、设计和执行证据文件及SHA-256。仅审报告、生产自测或缺执行条件不能通过；修复由原会话处理，复验另开全新会话，不复用生产或历史测试上下文。 |
| TEST-01 | 当前构建/配置、环境和所有必要前置基线明确，本期必需 AC 对应用例、执行结果与证据。 |
| TEST-02 | 关键正常/异常/边界/权限/恢复已检查，后台任务核验真实业务状态，未测明确列出。 |
| TEST-03 | 用例可重复，数据、执行方法、实际结果与证据足以复核，Mock与真实集成严格区分。 |
| TEST-04 | 适用性能/容量、兼容、无障碍、安全和可靠性使用项目确定环境及门槛。 |
| TEST-05 | 规格收敛完整检查，遗漏/矛盾/超范围实现得到明确处理，修复后受影响回归完成。 |
| TEST-06 | 缺陷严重度、状态和复验明确，阻塞项已关闭或正式豁免，修复记录不能冒充通过。 |
| TEST-07 | 仅AI产品执行适用质量/权限/行动结果与配置变更评测，普通产品不强套。 |
| TEST-08 | 报告范围、证据、未检、豁免、发布/停止/回退准备及业务接受分别记录，最终确认绑定版本。 |

## 共通通过条件

当前版本/指纹有效，清单逐项有实际证据，没有未解决或仅已修复未复验的阻塞问题。MD与HTML同源，原始报告不可覆盖。独立评审与用户阶段确认分开；正式豁免不显示全部通过。所有报告/请求/提示词存项目根验收记录目录。

## 项目补充规则

执行者据真实范围补充，不以模板默认条目代替本期检查清单；源规则变化须刷新受影响旧验收。
