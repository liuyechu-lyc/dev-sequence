# 最终测试独立执行入口

本入口承担新会话内的最终测试设计与实际执行，不只是审阅报告。读取共享 final-test-isolation.md、实际项目验收规则、本轮冻结请求与必要原文。

1. 在不继承生产历史的新会话开始；核对绑定身份和independentTestPolicy，不复用生产或任何历史测试会话。
2. 从需求/AC、设计、待测代码/构建及风险独立形成或修订测试计划、TC与覆盖。可参考已有用例，不能只审旧报告或照搬勾选。
3. 实际执行适用场景，记录预期/实际、方法、构建、环境、日志与业务结果。仅可写测试产物/证据/报告，不改受测源代码、业务要求或验收规则。
4. 逐项输出检查、缺陷和未测范围。pass时填写independentTest、真实TC列表、设计/执行证据、buildVersion、environment，以及至少各一份design/execution非空文件的项目相对path和sha256。
5. 无能力执行必需项时真实not_checked并回传，不消失、不由生产会话代测冒充通过。
6. 有交接ID时运行handoff-complete，并以完整信封作最终答复，宿主自动回到原会话。不得自行修改代码、确认阶段或向其他人发送消息。
7. 原会话修复后，复验必须再派发另一个全新会话。本轮历史问题可作为下轮冻结输入，不把本对话fork为复验。

## 轮次与历史问题

issues只列本轮新发现、新增问题点或重新打开的问题；相同问题沿用原ID。旧问题复验用verifications（issueId、result=pass/fail/not_checked、evidence、comment），简要关联原轮次，不复制已关闭问题全文。request.json的priorIssues包含未关闭问题及实际答复；先独立检查当前产物再核对，不能以生产者答复代替验证。受影响回归仍需执行并记录检查证据。原会话答复与修复写回提出轮次，不另建fix轮次；独立复验仍须新上下文和新review轮次。
