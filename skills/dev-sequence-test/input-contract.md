# 测试验收输入契约

## 接受的输入

需求/AC、适用UI/原型与技术方案；待测构建、环境、数据、权限；已有测试、变更范围、任务与风险。

## 最小进入条件

可验证要求、明确构建/配置与可用环境。环境缺失可交付计划/静态检查，但未执行部分不能验收通过。

## 接入与裁剪

- 登记来源、路径/URL、版本/内容指纹、适用范围、事实/假设/缺失与授权。已有外部资料可直接使用；以 `输入基线.md` 解释等价角色。
- 小修改可以合并文档，复用未受影响成果并说明理由；不因模板强造界面、架构或全套文档。
- 必需内容仅因未提供而缺失不能标为不适用。阻塞规则先澄清；非阻塞假设明确标记，不当事实。
- 本阶段验收请求必需角色：review-standard、prd、prototype、tech、code。
- 图像实际查看，HTML实际渲染，URL实际访问；超出能力、缺依赖或不可访问部分列为未核实。

## 强制新会话与派发时点

原会话只准备有效需求/AC、设计、待测版本/代码、环境、数据、权限和范围，并提供真实producer-session。最终计划、TC、实际执行与报告由新会话独立完成；已有用例仅作参考。不得要求先有最终测试报告才能发起本节点。请求artifacts指向待测版本或清单，代码作为实际上下文；不要把新增测试产物的整个项目目录冻结为输入。缺执行能力不能通过，仍需回传真实未检查结果。
