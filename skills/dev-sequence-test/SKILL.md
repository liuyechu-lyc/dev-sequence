# Dev Sequence · 测试验收

将本目录记为 `STAGE_ROOT`，同级 `../dev-sequence` 为 `CORE_ROOT`。这属于本套件的共享运行时；不要求先调用总控，不读取其他研发 skill。独立安装时安装器会同时携带共享运行时。

1. 读取 `CORE_ROOT/references/core-contract.md`、`CORE_ROOT/references/final-test-isolation.md`、[输入契约](input-contract.md)及必要业务基线；不继承生产对话。
2. 原会话只准备当前需求/AC、适用设计、代码/构建、环境、权限和范围，登记真实producer-session。不得先由生产会话完成最终测试，再只交报告给新会话审阅。
3. 先按 `CORE_ROOT/references/review-choice.md` 让用户选择本模型、第三方或暂不验收并登记真实依据；无有效选择不派发，只有明确复用授权才沿用。选择本模型后按 `CORE_ROOT/references/automatic-handoff.md` 派发全新独立测试会话；此处明确请求 `fork_turns=none` 的同模型测试子代理，不继承生产历史。第三方模式输出相同独立执行职责的完整提示词。
4. 新测试会话按 [工作流](workflow.md) 从需求独立形成或修订计划/TC、实际执行、核对预期与实际并生成报告；可参考既有用例，不得只照搬勾选。允许写测试产物与证据，不能改受测代码、业务基线或验收规则。
5. 原会话派发前按 [验收标准](review-standard.md) 建立并冻结节点根 `.review-skill.md` 与 `验收规则.html`；新测试会话遵循实际规则，不自行改门槛。规则、输入版本和独立设计/执行证据纳入结果，正式验收材料仍在项目根 `验收记录/`。
6. 完成后自动回传原会话。未通过由原会话修复，更新待测版本并创建新review轮次，再派发另一个全新会话独立复验和受影响回归；禁止复用生产或历史测试会话。
7. pass结果必须填写independentTest、实际TC、构建/环境、设计/执行证据文件及SHA-256；缺条件如实not_checked后仍回传，不得由原会话代测冒充通过。源码自测、报告审阅或仅script检查不能替代本节点。
8. 通过后按真实授权确认与交付。自动化模式不取消新会话强制要求；缺信息、权限、隔离能力或有规则冲突时暂停具体受影响动作。
外部 skill 可按需协作；调用前读取 `CORE_ROOT/references/external-skills.md`。规则冲突或分歧列明双方出处和影响，询问使用者；不自行决定优先级，不暂停无关工作。

输出：测试计划、TC用例、执行与证据、DF缺陷与复验/回归、规格收敛报告；测试报告.md及HTML、交付建议和确认。

验收目录遵循`CORE_ROOT/references/review-layout.md`：根部只保留验收记录总MD/HTML，各阶段验收子目录每轮一对MD/HTML，包含问题、建议、答复和处理/不处理解释；请求/快照/冻结JSON/提示词在本轮`.过程/`，机器账本在`.dev-sequence/reviews/`。发现、答复和修复归属同轮，使用reply写回问题提出轮次；下一次独立验收/复验才增加轮次，不另建fix轮次。旧问题复验简要关联，已关闭项不再重复列为新发现，未关闭项不因省略自动消失。总览按轮次组织，HTML支持折叠问题与答复。原始结论冻结，阅读视图同源追加处理链。业务节点根仅规则与业务产物，源码不搬迁。
