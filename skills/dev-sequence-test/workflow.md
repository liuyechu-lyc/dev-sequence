# 测试验收工作流

**强制：以下测试设计、执行与报告工作必须在新会话内完成，不是原会话测试后另开会话审报告。原会话仅准备待测基线、修复及接收结果。读取共享 final-test-isolation.md。**

1. 新会话从本期AC、变更与风险独立形成或修订计划和TC；可以参考技术/开发阶段资料，但必须自行判断覆盖并补齐适用场景。记录本会话身份、构建、配置、账号、数据与环境。
2. 用稳定 TC 关联 FR/规则/AC、前置、步骤、预期、实际、证据及 DF。覆盖关键正常、异常、边界、权限与恢复；界面和业务状态均核对。
3. 实际执行适用的单元/契约/集成/E2E及非功能验证；按项目风险裁剪，不强制所有类型。Mock、原型演示、静态检查、真实集成和未测试分开报告。
4. 规格收敛并行检查当前代码相对需求/方案/任务的 missing/partial/contradicts/unrequested。检查任务即使已勾选也核对最终行为；只写发现，不直接改源代码。
5. 将结果自动回传原会话，由实施侧追加可追溯修复任务并修复；更新待测版本后另开全新会话独立复验及受影响回归，不复用生产或历史测试会话。缺陷使用稳定 ID；不靠修改需求或清空历史达到收敛。两轮同类问题无进展先诊断。
6. 非功能使用已确认操作、数据量/负载、环境和门槛；AI产品按数据/模型/提示/检索/工具版本执行评测、重复试验及必要人工校准，核验最终行动结果。
7. 检查发布观测、停止和回退准备。测试通过、Converged、业务接受和允许发布分别表述，不能相互替代；不自动部署。
8. 在独立测试会话核对方法、实际证据与结论，生成本轮报告并回传；结果包含independentTest、TC、设计与执行证据文件及SHA-256。缺陷复验通过后绑定当前构建形成交付确认；未执行/限制/正式豁免显著列出。

## 产物与源文件

测试计划、TC用例、执行与证据、DF缺陷与复验/回归、规格收敛报告；测试报告.md及HTML、交付建议和确认。

MD 正文、结构化契约和任务各有单一权威来源，HTML从源生成。登记业务版本、来源版本、构建/代码快照和追溯入口。公共验收工具不代替业务产物生成或真实执行；由当前 Agent 使用环境可用工具完成。

## 自检与关卡

对照 `review-standard.md` 逐项检查，填写真实证据和未检查项；源缺失、证据不足或有阻塞不能判通过。再进入共享独立评审协议；修复后新轮次复验。默认人工阶段确认，已有明确预授权按真实依据登记。
