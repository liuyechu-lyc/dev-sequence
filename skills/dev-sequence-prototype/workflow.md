# 原型设计工作流

1. 完整读取公共原型源契约 `prototype-source-contract-v3.md`；用控件/图解说明页前读对应专项标准。仅用本包内框架与生成器。
2. 绑定 PRD 与原型业务版本，确认支持终端和埋点文档或无需埋点。以 app/prototype.config.json 统一维护导航、页面、概述和追溯；页面放 app/pages，规范放 app/specs。
3. 复用已确认业务 UI 令牌。模块 key 与 data-ds-spec-anchor 对应，ds-* 为框架保留命名空间。源页面不手抄查看器、运行时、标注和通信代码。
4. 覆盖业务主流程、关键异常、空/加载/错误/权限及提交恢复。明确模拟边界、失败触发、重置、刷新与切页保留。复杂控件和抽象流程用独立说明页，不重复业务规则。
5. 先源校验，再构建，再产物校验。源文件是维护入口，最终内嵌 HTML 可独立打开；相同输入构建 ID 相同，内容变化需换 ID。
6. 实际浏览器验收业务与框架：长短页切换、真实内容高度、多终端、标注、Space拖拽、局部滚动、一级及嵌套浮层关闭恢复。静态结构通过不能代替实际交互验证。
7. 独立评审、修复复验后确认页面范围与交互。业务/交互改动同步规范；纯视觉修改说明影响。新迭代才按授权重置旧红标，不在普通修复时清空历史。

## 产物与源文件

app/ 注册表、页面及独立规范；index.html 与独立页面；概述、演示/重置/模拟边界、追溯及验收确认。

MD 正文、结构化契约和任务各有单一权威来源，HTML从源生成。登记业务版本、来源版本、构建/代码快照和追溯入口。公共验收工具不代替业务产物生成或真实执行；由当前 Agent 使用环境可用工具完成。

## 自检与关卡

对照 `review-standard.md` 逐项检查，填写真实证据和未检查项；源缺失、证据不足或有阻塞不能判通过。再进入共享独立评审协议；修复后新轮次复验。默认人工阶段确认，已有明确预授权按真实依据登记。
