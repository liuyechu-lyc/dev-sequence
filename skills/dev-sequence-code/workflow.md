# 代码编写工作流

1. 检查真实工作目录、已有改动、工程原则、输入版本和一致性检查。保留无关改动，不擅自初始化/切换仓库或迁移源码。规则清单勾选不等于代码完成。
2. 按依赖顺序执行任务。任务状态为 todo/in-progress/blocked/implemented/verified，已实施需产物，已验证需对应实际证据。基础工作与独立业务切片分开，适用测试随实施形成。
3. 实现业务、权限、字段、状态、错误与恢复；按风险检查冲突、重复、超时、取消和补偿。前端提示与真实业务结果一致。
4. 新发现需求问题回写需求；设计偏离形成 ADR 并回写方案，更新关联任务与追溯，不能偷偷改规则迎合代码。
5. 执行已约定构建/静态检查及适合本次风险的测试。测试核对行为与关键不变量，避免镜像实现断言。Mock 与真实集成分别记录，不声称未执行的外部效果。
6. 对照规格/方案/任务检查当前实现，关注 missing/partial/contradicts/unrequested；必要修复追加来源明确的任务，不重写或重编号历史。Converge式检查只评估与提出剩余任务，业务代码由实施步骤修改。
7. 连续两轮同类问题无进展时先诊断规则、设计、依赖或环境，不无限追加重复任务。范围外新增先评估和确认，不能顺手扩展产品。
8. 新上下文独立代码评审，处理后复验。确认绑定提交或内容快照、实现范围和已知限制；不把实施完成当成最终测试/发布许可。

## 产物与源文件

实际仓库中的代码/配置/必要测试；tasks.json状态与证据；运行/迁移说明、设计偏离和检查结果；独立代码评审与实施确认。

MD 正文、结构化契约和任务各有单一权威来源，HTML从源生成。登记业务版本、来源版本、构建/代码快照和追溯入口。公共验收工具不代替业务产物生成或真实执行；由当前 Agent 使用环境可用工具完成。

## 自检与关卡

对照 `review-standard.md` 逐项检查，填写真实证据和未检查项；源缺失、证据不足或有阻塞不能判通过。再进入共享独立评审协议；修复后新轮次复验。默认人工阶段确认，已有明确预授权按真实依据登记。
