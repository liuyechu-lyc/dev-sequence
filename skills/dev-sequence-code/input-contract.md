# 代码编写输入契约

## 接受的输入

需求/AC、适用原型、技术方案及任务；仓库、现有改动、运行环境与测试。

## 最小进入条件

明确修改范围、业务行为/成功条件、设计与任务说明。小修复允许同一简短基线满足多个角色，必须有真实规则与验证方法。

## 接入与裁剪

- 登记来源、路径/URL、版本/内容指纹、适用范围、事实/假设/缺失与授权。已有外部资料可直接使用；以 `输入基线.md` 解释等价角色。
- 小修改可以合并文档，复用未受影响成果并说明理由；不因模板强造界面、架构或全套文档。
- 必需内容仅因未提供而缺失不能标为不适用。阻塞规则先澄清；非阻塞假设明确标记，不当事实。
- 本阶段验收请求必需角色：review-standard、prd、prototype、tech、tasks。
- 图像实际查看，HTML实际渲染，URL实际访问；超出能力、缺依赖或不可访问部分列为未核实。
