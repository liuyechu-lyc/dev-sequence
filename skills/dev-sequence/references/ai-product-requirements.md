# 产品 AI 能力的条件要求

## 启用条件与用途

仅在被交付产品本身使用 AI 完成用户任务时读取本参考，并把适用内容接入 PRD、原型、技术方案与验收。开发、设计或评审过程使用 AI 不触发本分支。范围深度随任务、行动权限和失败影响裁剪，不要求所有 AI 功能采用 Agent 架构。

PRD 定义产品行为和质量；技术方案确定模型、提示词、检索、工具和编排等实现。保持现有 FR/AC 等编号，新评测条目可按项目现有约定编号。

## 1. 需求中的最低契约

| 范围 | 需要明确的产品要求 |
|---|---|
| 任务与边界 | 用户任务、适用输入、可完成/不可完成情况、成功和失败；何时澄清、拒绝或转人工 |
| 数据与上下文 | 允许来源、用户/组织权限、时效、缺失/矛盾处理、上下文及记忆范围；适用的日志/敏感数据保留和删除 |
| 输出契约 | 结构和必需内容、事实与推断区分、引用、允许多样化部分、必须一致的约束与禁止行为 |
| 用户控制 | 编辑、采纳、重试、取消、撤销、恢复和人工接管的范围及结果 |
| 行动权限 | 建议、草稿或执行的边界；确认的对象/范围/时机、执行权限、重复动作和失败补偿 |
| 运行约束 | 首次反馈与完整结果时间、超时、降级、成本/配额、部分结果和工具失败后的行为 |
| 外部输入与输出校验 | 外部内容中的指令不自行扩大已授权任务/权限；按业务要求校验生成结果和工具参数，不依赖未经校准的置信分数决定高影响行动 |
| 反馈与观测 | 业务任务完成、采纳/编辑、失败原因等适用口径；反馈处理去向与责任人 |

## 2. 原型与技术方案的对应内容

- 原型按实际能力展示输入/来源、生成中、需澄清、无依据、结果编辑、失败恢复、等待确认及人工接管等状态，并注明模拟范围与触发方式。原型样例不证明真实模型质量、授权或工具执行已经实现。
- 技术方案给出上述契约如何被实现和验证：数据/工具权限、输出校验、执行确认、幂等与补偿、超时/成本限制、观测以及回退。架构选择由实际任务决定。
- 对自动行动应有真实业务结果的验证方式。例如验证记录确实创建，而不是仅检查回复声称创建成功。

## 3. 评测条目与证据

| 字段 | 要求 |
|---|---|
| 关联任务 | FR/AC、用户任务与适用范围 |
| 输入与环境 | 样例、上下文、权限、数据/工具状态和基线版本 |
| 行为约束 | 必须满足和不得发生的行为；可接受的有效结果变化 |
| 样本构成 | 代表性正常、困难、边界、无依据和越界输入；样本来源与限制 |
| 评分与门槛 | 可执行评分规则、通过条件及业务依据；自动/模型评分按需要人工校准 |
| 波动与汇总 | 任务输出有波动时明确重复试验、抽样和统计口径；区分任务完成、内容质量、时延与成本 |
| 最终结果 | 工具和外部系统实际状态的核验；拒绝/取消后是否避免未授权副作用 |
| 失败与责任 | 失败分类、实际结果、证据位置、复核人及处理计划 |

不设通用“准确率达到某固定比例”的门槛。离线评测、原型演示和真实使用结果分别标记，未执行的评测保留为未检查。

## 4. 变更与回归

模型、提示词、检索/数据来源、工具权限或编排方式发生有效变化时，评估受影响任务与质量门槛，更新版本并执行对应回归；不因无关视觉修改重跑全部评测。评测计划和结果可独立成附件，但 PRD 保留质量契约、门槛、责任及附件版本，验收报告绑定实际被测版本。
