# 图解说明页标准

## 1. 定位

图解说明页是项目概述页、业务功能页、控件说明页之外的第四类原型页面，使用
`kind: "diagram-guide"` 声明。它不是可操作的业务界面，而是用图形与文字说明抽象流程、
架构、时序、状态、数据流或对应关系的单一内容源。

图解说明页标准化“说清楚的方法和页面骨架”，不固化某种图形语法、项目角色、
节点数量或排版方向。

## 2. 使用边界

适合：业务/系统上下文、主流程与分支、跨角色泳道、业务时序、状态迁移、实体或页面对应关系。

不适合：

- 可直接操作的业务界面：放入业务功能页。
- 控件字段、类型和状态枚举：放入控件说明页。
- 项目背景、目标、全局规则和页面目录：放入项目概述。
- 部署拓扑、服务拆分、数据库和 API 实现时序：放入 tech 阶段技术方案。

## 3. 页面声明

```json
{
  "id": "example-flow",
  "kind": "diagram-guide",
  "title": "示例核心流程",
  "output": "example-flow.html",
  "source": "pages/example-flow.html",
  "navGroup": "project-diagrams",
  "businessEnd": "项目图解",
  "description": "说明角色、节点和核心流程的关系。",
  "versionChanges": ["新增核心流程图解"],
  "changeType": "new",
  "changeImpact": "business",
  "viewports": {
    "default": "pc",
    "supported": [{ "type": "pc", "width": 1440, "height": 900 }]
  }
}
```

- 使用独立项目图解导航分组，不混入业务页或控件说明页。
- 在项目概述单独成组统计，不计入任何实际业务端。
- 不声明 `specs`，或显式使用 `enabled: false`；不生成红蓝标注。
- 流程或关系改动可使用 `changeImpact: "business"`；页面正文即变更说明源，不另建技术规范复制。
- 默认使用 PC 评审画布，但仍按真实阅读场景声明终端。

## 4. 中性页面骨架

以下模块按需求增删，不保留无内容占位：

1. **页面说明**：用途、覆盖范围、阅读对象、不在本页说明的内容。
2. **阅读方式**：主阅读方向、图例、颜色、线型、节点形状和编号含义。
3. **主图**：使用 SVG 或语义化 HTML 承载流程、架构、时序、状态或关系。
4. **节点与关系解释**：解释关键节点职责、连线语义、输入输出及对应口径。
5. **分支与例外**：明确条件、中断、回退、并行、不支持组合和待确认事项。

## 5. 图形表达规则

- 每张图只使用一个主阅读方向；分支线标注条件，回流线与主流程视觉区分。
- 泳道必须声明责任角色；时序图必须有生命线与消息方向；关系图必须标注方向、数量或包含语义。
- 同一概念在项目内使用同一名称、颜色和形状；颜色不是唯一的语义编码。
- 优先使用内联 SVG，保留可选择文字并提供 `title`/`desc`；Mermaid 仅可作为生成工具，交付前固化为 SVG。
- 不默认使用 Canvas、纯位图或外部 CDN；只有超大节点量或持续高频重绘时才选 Canvas，并补充等价文本说明。
- 只允许缩放、平移、高亮、展开解释等阅读辅助交互；如果交互在模拟业务操作，应改建业务功能页。

## 6. 验收

- 不阅读段落时能从标题、图例、节点和连线识别主结论；阅读文字后不存在未定义节点或连线。
- 正常缩放比下文字、箭头、条件和泳道标题可读，无裁切、遮挡、错连或无意义交叉。
- 主流程必须有起点、结果和闭环；异常、回退、并行及跨角色交接有明确表达。
- 页面可通过 `file://` 独立打开，无外部运行时依赖，Index 缩放、Space 拖拽和触摸板平移不受影响。
