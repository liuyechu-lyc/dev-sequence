# 控件说明页标准

## 1. 定位

控件说明页是项目概述页、业务功能页之外的第三类原型页面，使用
`kind: "component-guide"` 声明。它不是实际业务页面，而是复杂控件的单一规则来源，
用于集中说明控件结构、字段规则及类型、状态、样式等组合。

控件说明页标准化的是“说明方法和页面骨架”，不是具体内容形式：

- 列表、卡片、表格行、弹窗、抽屉、浮层等载体均由具体需求决定。
- Skill 不规定必须存在列表或弹窗，也不沉淀某个项目的控件结构和业务文案。
- 页面可说明一个控件，也可说明职责紧密、需要共同核对的一组控件。

## 2. 何时创建

满足以下任一情况时，优先创建控件说明页：

- 同一控件被两个或以上业务页面复用。
- 控件具有多个类型与多个状态，组合核对成本较高。
- 不同类型的字段来源、拼接或展示规则不同。
- 同一套控件规则已经需要在多个业务页面技术规范中重复维护。
- 研发或测试需要使用一维、二维或分组枚举核对完整状态。

简单列表、单一状态控件或只在一个业务模块出现的普通字段，继续在业务页面控件级技术规范中说明，不强制拆页。

## 3. 与业务页面的职责边界

业务功能页负责页面和载体层规则，包括数据范围、筛选、排序、分页或加载、空状态、
权限、批量操作、刷新、列表点击结果及页面间流转。业务页只展示足以说明真实场景的代表性实例，
不为了枚举状态而膨胀业务 DOM。

控件说明页负责控件内部规则，包括结构、字段数据源、生成与拼接、显隐、状态、操作样式、
类型差异和不支持组合。被抽离的规则只在控件说明页维护，业务页面技术规范通过 `pageId`
引用，不复制第二份完整定义。

业务页面中的真实控件 DOM 与控件说明页中的示意 DOM 可以不同；只要两者遵循同一份字段和状态规则即可。

## 4. 页面声明

```json
{
  "id": "example-component-guide",
  "kind": "component-guide",
  "title": "示例控件说明",
  "output": "example-component-guide.html",
  "source": "pages/example-component-guide.html",
  "navGroup": "prototype-guides",
  "businessEnd": "原型控件说明",
  "description": "说明复杂控件的结构、字段规则与状态组合。",
  "versionChanges": ["新增示例控件说明页"],
  "changeType": "new",
  "changeImpact": "none",
  "viewports": {
    "default": "pc",
    "supported": [{ "type": "pc", "width": 1440, "height": 900 }]
  }
}
```

- Index 左侧使用独立“原型控件说明”分组；该分组不得混入业务功能页。
- 项目概述将控件说明页单独成组统计，不计入任何实际业务端的页面数量。
- 控件说明页仍必须声明兼容终端。默认优先使用便于横向比较的 PC 评审画布，
  具体宽度由内容决定，不强制固定为 1440、1580 或 1600。
- 页面不声明 `specs`，或显式使用 `enabled: false`。Index 隐藏技术规范抽屉。
- 页面不生成红蓝标注。详细标注通过页面内结构说明、字段规则和枚举内容表达。

## 5. 标准模块

以下模块按需求选择，不要求空模块占位：

1. **控件页面说明**：说明用途、覆盖范围、被哪些业务页面使用、目标业务终端和不在本页描述的内容。
2. **阅读方式**：说明占位符、维度、颜色、状态标签及阅读顺序。
3. **控件结构**：使用 `{字段名}` 表示动态数据，固定标签、图标和按钮保留真实内容。
4. **字段描述规则**：每个字段独立描述数据来源、生成/拼接、显示条件、空值处理、状态和交互；禁止合并语义不同的字段。
5. **控件枚举**：根据实际需要选择一维、二维或分组枚举。
6. **例外规则**：明确不支持组合、兼容逻辑、历史表现和“本期无需实现”内容。

当字段规则表支持横向滚动时，应明确局部滚动消费规则；当表格会妨碍 Index 触摸板拖拽时，
可以按项目需要提供锁定/解锁，但该交互不是控件说明页的固定要求。

## 6. 枚举选择

- 只有一个有效变化维度时使用一维枚举。
- 两个维度都会显著改变控件结构或样式时使用二维矩阵。
- 三个及以上维度、存在大量无效组合或矩阵难以阅读时使用分组枚举。
- 不支持、本期不实现、历史兼容的组合必须显式标识，不以空白单元格代替规则。

## 7. 业务技术规范引用

技术规范区块只保存稳定 `pageId`。`references` 只能放在具有 `key`、`title` 的规范
section 上，不能放在页面、模块或控件条目层级，避免数据通过校验却没有可见入口：

```json
{
  "key": "component-guide-reference",
  "title": "控件详细规则",
  "content": "本模块只维护列表排序与页面交互；控件字段和状态由引用页面统一维护。",
  "references": [
    { "pageId": "example-component-guide" }
  ],
  "changeType": "modified"
}
```

Index 根据项目注册表解析页面标题并显示可点击的“查看《页面标题》”入口。点击后由 Index
切换页面并重置画布位置；业务 iframe 不直接控制其他页面，也不增加页面间通信协议。

引用目标必须存在、不得引用自身，并且必须是 `kind: "component-guide"` 的控件说明页。
页面改名、调整菜单或输出文件名时，只要 `pageId` 不变，引用继续有效。
