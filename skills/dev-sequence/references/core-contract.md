# 共享执行契约 v1

## 定位、独立运行与权限

- 用户指定项目优先；未指定时使用当前工作区。正式产物保存在目标项目，不放入安装的 skill 目录。
- 本总控负责治理本契约，六个流程直接读取同一文件。仅按任务范围读取本阶段资料，不完整加载整套技能。
- 最小输入是事实、规则、约束和可验证目标，不是固定文件名。已有 PRD、设计稿、代码或外部说明可映射为等价输入；用 `输入基线.md` 记录来源、版本、事实、假设、缺失、适用角色和授权。不伪造缺失前置成果。
- 完整重做沿需求→UI→原型→技术→代码→测试保留各适用节点的当前成果与关卡；等价输入是内容复用机制，不是自行缩减用户要求的流程。只有用户明确阶段范围或事实不适用可裁剪。
- 新项目尚无工程布局时，源码、配置、开发/构建脚本、必要测试及运行说明集中 `代码/`；根保留项目导航和全局协作/来源文件。既有工程维持原位，用户要求迁移时同步修正运行/构建入口、依赖引用、文档和验证基线，保留旧冻结证据。
- 最终交付规则见 [final-delivery.md](final-delivery.md)。中间构建不能冒充所有节点通过后的最终交付。
- 小修改允许简短方案与任务说明；明确变化、关联 ID、有效规则、验证方法和复用理由。未知关键权限、结果或不可逆操作规则必须澄清；非阻塞项不阻断独立工作。
- 先读适用的 AGENTS.md、项目工程原则与现有资料。不自动搬迁目录，不覆盖定制文件，不无依据增加业务范围。用户授权不扩展到外部发送、发布和付费调用。

## 项目协作与来源

首次接入时缺失才创建 `项目理解.md` 和 `交互记录.md`。项目理解保存已确认目标、边界、架构、文件关系、稳定约束、当前阶段及风险；任务开始前阅读，变化时更新。不能代替当前 PRD。

交互记录按轮次追加用户完整原文、时间、最终结果摘要和返回时间，不存思考过程；没有消息提交时间时记录真实接收时间并注明。时间精确到秒、含时区；不补造历史。初始化工具只创建空记录壳，实际内容由执行者登记。

来源有路径/URL、版本或获取时间、可查内容和适用范围。URL 变动时以评审快照为准。图像/二进制必须由有能力的评审者实际查看；只有哈希和文件名不构成语义验收证据。

## 内容权威与稳定编号

| 内容 | 权威来源 |
|---|---|
| 目标、范围、业务规则、权限、数据口径、AC | 当前有效需求或等价输入基线 |
| 设计令牌、组件视觉、布局与断点规则 | 已确认 UI 规范 |
| 页面、控件呈现、交互及状态演示 | 当前原型及独立规范 |
| 架构、数据、接口、部署、工程取舍 | 当前技术方案与 ADR |
| 实际运行结果 | 对应构建与环境的测试证据 |

保留 US/FR/PG/FL/FD/AC/BR 等既有编号，不因模板升级重编号。任务 T、用例 TC、缺陷 DF、决策 ADR 使用各自稳定命名空间。公共规则只在权威来源定义，其他产物引用编号与版本。文件较新不自动拥有更高权威。

尚无原型时在 PRD 附录维护初始追溯；进入原型后，以 `原型/app/prototype.config.json.traceability` 为唯一结构化映射源，PRD 引用它。无 UI 项目以 `需求/追溯.json` 维护。同一行可扩展 `techRefs`、`taskIds`、`codeRefs`、`testIds`；实际文件定位用 `links`。任务清单维护任务内容与依赖，不再手工复制完整业务映射。

结构工具只能检查引用、缺失和基线，不证明业务语义一致；语义冲突由独立评审检查。

## 各阶段共同交付字段

目标与排除范围、输入基线、事实/假设/待决项、当前产物及版本、追溯、真实自检、独立验收、阶段确认。MD 为内容源时 HTML 从其生成，避免双份手改。构建生成物不作为维护源。

非功能门槛绑定本项目操作、环境、数据规模/负载、指标和测量方法，不强加统一毫秒数或覆盖率。按风险安排有意义的测试，不为轻微可逆修改机械写测试。

## 变更与失效

变更先更新权威正文及变更记录，识别关联 ID；沿追溯登记每个后续产物需更新/复用及理由，再更新版本和证据。工具刷新输入内容指纹，必要上下文或规则变化使相关旧结论失效；未受影响部分明确复用。文件摘要、模型自述和模拟成功不能替代真实结果。

验收规则 MD 与 HTML 放在节点根目录：`.review-skill.md` + `验收规则.html`。面向使用者的记录按[验收阅读结构](review-layout.md)放在项目根`验收记录/`：根部仅`验收记录总.md/.html`，各阶段子目录内每轮一份MD/HTML。机器账本放`.dev-sequence/reviews/`，快照、请求、提示词和冻结JSON放所属轮次`.过程/`。问题和答复同源；发现、答复及修复留在同一轮，仅下一次独立复验新增轮次。总览以轮次组织，旧项复验简要关联，已关闭项不在后续问题清单重复展示；原始结果冻结，阅读视图可追加显示处理与复验，不在业务节点重复存报告。

本模型独立验收和明确授权的全自动执行遵循 [自动交接协议](automatic-handoff.md)：新上下文验收完成后由宿主自动回传原对话，原对话重新校验并实际处理结果。足够信息、权限、执行条件和明确自动授权齐备时，在本轮范围内持续修复/复验/确认/推进；不因每个阶段机械要求用户再说继续。规则冲突、授权缺口、环境能力缺失和连续无进展有明确停止/诊断点。它不扩大发布或外部写入权限。

仅产品本身含 AI 能力时读取 [AI 产品要求](ai-product-requirements.md)。开发或评审使用 AI 不触发 AI 产品专属要求。

最终测试验收的设计和执行必须整体放到新会话，不能由原生产会话完成后只把报告交给新会话审阅。修复回原会话，复验再开新会话；这是单环节、组合、全链路和自动化模式共同的强制关卡，见 [最终测试隔离](final-test-isolation.md)。
