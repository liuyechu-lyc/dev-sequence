# 外部 Skill 协作与分歧处理

各阶段可配合外部设计、文档、研究、框架、代码和测试 skill。它们是可选协作者，本套件运行不依赖其安装。

1. 记录名称、来源位置、版本或内容指纹、用途、阶段、输入输出及生效约束。调用前读取其真实规则，不按名称猜测。
2. 比对用户要求、当前流程规则、项目验收规则和外部规则。出现冲突或分歧时列明双方原文、精确文件位置、具体影响与可选方案，询问使用者。
3. 不自行规定当前 skill 或外部 skill 永远优先；也不把建议差异隐藏成默认取舍。只暂停受该决定影响的操作，其他已授权独立工作继续。
4. 用户决定写入 `规则决策.md`：决定 ID、规则双方、选择、理由、适用项目/阶段/版本、有效期及真实消息依据。已有决定仍有效时沿用，不重复问；范围变化再确认。
5. 将决定反映到本阶段实施与验收标准；标准变化导致受影响旧验收 `stale`。不直接修改外部 skill 安装文件。
6. 外部产物进入本阶段相同验收流程，不能凭外部“已完成”直接通过。规则决定不能越过运行平台强制约束或把未执行改写成已执行。

建议询问格式：

> 当前规则要求 A（来源：路径及条目），外部规则要求 B（来源：路径及条目）。两者在 C 上无法同时满足，会影响 D。请选择采用 A、采用 B，或指定组合；选择仅应用于所说明范围。
