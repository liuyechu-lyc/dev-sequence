# 验收方式选择

## 先交付，再选择

每阶段先形成可阅读成果和适用自检，提供当前版本与入口，然后让用户选择：

- 本模型自动验收：新建不继承生产对话的同模型上下文，实际检查并自动回传。
- 第三方验收：交付资料包和完整提示词，等待第三方真实结果，不启动本模型评审。
- 暂不验收：保存产物和用户决定；该选择不产生验收通过、阶段接受或正式豁免，不能据此自动推进依赖阶段。

最终测试是先冻结待测版本、必要基线与范围，交付这些入口后选择；选择验收才派发独立会话设计并实际执行测试，不由生产侧先做最终测试报告。

选择问题必须写明阶段、产物版本及入口。有交互问答工具时提供三项选择，否则在对话中明确提问。没有答复时等待该选择，继续不依赖它的自检或整理；超时、默认勾选、工具可用、没有反对都不算选择。不为展示菜单而丢弃用户已给出的明确选择。

为减少重复询问，可以在问题中明确「本阶段及修复后的复验采用哪种方式？」并记录完整问题与答复；用户选择即覆盖所写范围，使用`--reuse stage`。若只问本轮，则保持`--reuse once`，不自行扩展范围。

「完整链路」「继续实现和测试」「重新验收」「全自动开发」可以表达工作范围或执行意图，单独不能证明选定了本模型、第三方或跳过。已有automation配置也只表示执行动作的授权，不代替验收方式。两类依据均须引用真实用户原文；不得拿自己先前生成的review-only配置反推用户选过。

## 记录与复用

用`review-choice`在`.dev-sequence/reviews/验收数据.json`追加实际选择。必须登记用户、可定位消息来源、原文、方式及阶段范围。默认`--reuse once`，仅用于下一独立验收轮次；后续复验或重新发起验收须重新选择。只有用户明确授权本阶段后续验收沿用，才用`--reuse stage`。用户明确指定多个阶段及复用方式时可一次登记这些阶段，不重复询问已授权范围；不能自动扩展到未列阶段。

以下仅展示命令结构，执行时替换成真实答复，不得把示例当授权：

```sh
python3 "$CORE_ROOT/scripts/ds.py" --project "$PROJECT_ROOT" review-choice \
  --stages prd --method native --reuse once \
  --by "实际用户" --source "实际消息的可定位来源" --text "实际选择原文"
```

`method`为`native`、`third-party`或`skip`；多阶段用逗号分隔。选择本模型不等于授权自动确认/跨阶段推进；需要本模型自动回传时，再按`automatic-handoff.md`登记相应动作授权。选择第三方且由AI评审时`prepare --method agent`，人类评审用`--method human`。

重复登记同一消息不会恢复已消费的一次选择。切换方式、撤回或缩小范围后，旧派发不能借旧选择继续自动动作；已运行评审的真实结果仍可回传留档，后续动作检查新决定。旧轮次结果保持原样，不补造历史选择；旧的尚未派发轮次无选择记录时，应取得明确选择后创建新轮次。

`skip`只记录决定，不建立虚假的「通过」轮次，不抹除历史实际结果。当前尚无验收时保持待验收；有历史结果时仍显示其原始有效状态，并单列当前选择，不能将旧结果包装成本次新验收。

## 工具关口与边界

- `prepare --kind review --method agent|human`缺少有效选择、选择为skip或一次选择已用完时拒绝创建轮次。修复登记及本地script自检可继续，但不能冒充独立验收或阶段确认。
- `handoff-open`和`handoff-bind`要求本轮绑定的native选择；third-party不能被自动改成本模型。
- `status`、MD和新建HTML展示选择及依据；数据记录选择使用过的轮次。历史HTML页面壳保持既有规则，不为展示新增字段自动覆盖定制结构。
- 选择记录改变后，旧结果回传仍留档，自动路由停止并核对新决定。

工具能检查结构、范围与使用次数，不能证明原始消息真实或替用户做选择。执行者仍须实际呈现选择并如实登记；文件不是人类授权的替代品。
