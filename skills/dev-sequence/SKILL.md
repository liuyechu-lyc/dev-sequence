# Dev Sequence · 研序

将本文件所在目录记为 `CORE_ROOT`；所有资源相对该目录解析。此包完全自带规则、模板、原型生成器和验收工具，运行不依赖任何其他研发 skill。Python 工具仅用标准库，支持 Python 3.10+。

## 开始与范围

1. 读取 [共享契约](references/core-contract.md)。先读取项目现有 `项目理解.md`、有效需求及本轮指定资料，保护已有文件和仓库改动。
2. 判断是单阶段、组合还是全链路；只执行已授权范围。用户要求「按研序重新做一遍／完整重做／完整流程」时采用六阶段全链路，不把随附旧需求、旧原型或既有代码自动当成裁剪授权。旧成果可引用、复用未变内容，但本轮各适用节点仍须有当前有效成果、版本、追溯和验收；只有用户明确指定单阶段/组合或事实不适用时才裁剪，并记录依据。普通小修改继续接受等价输入，不强制重跑无关阶段。
3. 按下表读取所选流程的 `SKILL.md`。这些是本套件安装时的同级目录；直接调用流程 skill 也使用相同契约，不必先调用本总控。

| 阶段 ID | 同级 skill | 默认项目节点目录 |
|---|---|---|
| prd | `../dev-sequence-requirements/SKILL.md` | `需求/` |
| ui | `../dev-sequence-ui/SKILL.md` | `UI设计/` |
| proto | `../dev-sequence-prototype/SKILL.md` | `原型/` |
| tech | `../dev-sequence-tech/SKILL.md` | `技术方案/` |
| code | `../dev-sequence-code/SKILL.md` | `代码/`（新项目含源码、脚本、测试及运行说明；既有工程保留实际位置） |
| test | `../dev-sequence-test/SKILL.md` | `测试验收/` |

先检查安装资源。缺少所选流程时说明缺失的套件目录，不改用其他 skill，不从用户机器的旧技能目录取资源。安装器可以只安装本总控共享运行时和指定流程。

## 编排与关卡

- 默认完整链路：prd → ui → proto → tech → code → test。无 UI 项目按事实声明 ui/proto 不适用；既有成果有效时引用复用。
- 各阶段按自己的输入契约、工作流和验收标准执行。全局只管理来源、版本、追溯、评审、确认与变更影响。
- 先完成具体可审阅成果和适用自检，交付阅读入口，再按[验收方式选择](references/review-choice.md)让用户明确选择「本模型自动验收 / 第三方验收 / 暂不验收」。没有有效选择不得准备或派发独立验收；完整链路授权不代表选定本模型。用户明确授权复用时按其阶段范围沿用，否则新轮次重新选择；不能把Agent自行写入的配置当作人类答复。
- 选择本模型验收后，读取 [自动交接与执行](references/automatic-handoff.md)。方式选择与自动执行授权分别核对；用新上下文同模型子代理独立验收，完成结果自动回传；原对话实际消费结果、修复/复验或推进。此处明确请求隔离评审子代理，使用 `fork_turns=none`，不继承生产历史。第三方只交付资料和完整提示词；暂不验收不产生通过或豁免，也不自动推进依赖阶段。
- 最终test节点必须在新会话中独立设计并实际执行测试，不能只审阅原会话报告；派发在最终计划/执行/报告形成之前。读取 [最终测试强制隔离规则](references/final-test-isolation.md)。原会话修复后，复验另开全新会话，不复用生产或历史测试上下文，保留自动回传闭环。
- 每阶段分别记录「验收状态」和「阶段确认」。默认人工确认；用户已预授权的自动推进继续有效，须记录实际授权依据，不能为缺证据自动确认。
- 当前范围验收通过且确认有效才推进依赖阶段。正式豁免必须有范围、理由、真实确认人和依据，不能显示为全部通过。
- 上游变化按追溯判断影响；旧报告冻结保留，受影响结论 `stale`，修复后 `awaiting-verification`，复验后才能通过。
- 调用外部 skill 前读取 [外部协作规则](references/external-skills.md)。有冲突或分歧时向用户说明双方规则和影响，等待选择；只暂停依赖该决定的部分。

## 验收记录的交付结构

总览只保留`验收记录/验收记录总.md`与`.html`，各阶段分别建`需求验收记录/`、`UI验收记录/`、`原型验收记录/`、`技术方案验收记录/`、`代码验收记录/`、`测试验收记录/`，每轮一份MD和HTML。总览按阶段、轮次、问题与答复组织；发现、答复和修复归属同轮，仅下一次验收/独立复验增加轮次。不另建fix轮次，主对话使用reply登记实际处理。旧项复验简要关联到原记录，已验证关闭且未再发现异常的项不在后续问题清单重复展示；未关闭项保留编号、状态和入口，不能靠省略通过。HTML支持轮次、问题、答复折叠及全部展开/收起。问题、建议、答复与处理结果同源汇总；快照和交接等放本轮隐藏过程目录。HTML固定页面壳与内嵌JSON分离，平时只更新数据块。执行前读取[阅读结构与数据维护](references/review-layout.md)，不再把内部过程文件平铺为交付物。

轮次在机器源中按编号末尾追加，回传结果补入对应轮次，不重复追加同轮。MD/HTML阅读数据统一按结果导入时的`recordedAt`倒序；未回传或旧记录缺该时间时用`createdAt`，同一时刻按轮次号倒序。HTML按已排序数据顺序渲染，日常仍只更新JSON块。显示顺序不改变当前阶段结论的版本依据：阶段当前状态仍取最新编号轮次，旧轮次晚回传不覆盖它。

## 配套工具

在执行验收或初始化前读取 [验收协议与命令](references/review-protocol.md)。入口：

```sh
python3 "$CORE_ROOT/scripts/ds.py" --help
python3 "$CORE_ROOT/scripts/ds.py" --project "$PROJECT_ROOT" init --stages prd,ui,proto,tech,code,test
python3 "$CORE_ROOT/scripts/ds.py" --project "$PROJECT_ROOT" status
```

初始化只创建缺失文件，不覆盖现行项目规则；已有仓库不搬迁，不上传公网，不擅自安装外部工具或调用付费模型。Python工具不直接创建聊天；加载本skill的Agent按宿主适配实际创建独立验收上下文并收取通知。第三方手动验收仍输出完整提示词。能力不足要明确报告，不伪造自动化；工具只能校验隔离声明，不能证明平台真正隔离。

## 交付

执行[最终交付规则](references/final-delivery.md)：所有本轮适用节点的最新有效验收通过并接受后，才通过白名单生成项目根 `交付/`。中间预览、试包和诊断保留在节点或隐藏构建目录；不得提前生成最终交付后再补关卡。

说明本轮完成范围、入口、输入/产物版本、真实验证结果、独立评审与阶段确认状态、限制及下一步。不得把文档齐全、代码完成、Converged、测试通过、业务接受或允许发布混为同一状态。
