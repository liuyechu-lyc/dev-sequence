# 产品需求规划工作流

1. 识别小修改/常规迭代/复杂业务，区分事实、假设与建议；未知数据标待测量，不编造基线。
2. 定义目标、范围与排除、优先级理由、业务成功指标和上线验收条件；两者区分。
3. 梳理角色权限、数据归属、业务对象、生命周期、流程状态、字段及公共规则；正常、关键异常、取消、中断、恢复和重复操作按需覆盖。
4. 以 Given-When-Then 等可复现方式定义 AC，保留 US/FR/PG/FL/FD/AC/BR 编号，建立初始追溯。非功能要求绑定环境、负载、目标口径和测量方法。
5. 更新当前有效正文与独立变更记录；澄清结论回写正文，阻塞项在依赖执行前解决。仅产品含 AI 时补读 AI 要求。
6. 产出后核对业务自洽、来源、可执行性和缺口，完成自检、独立评审、复验与业务范围确认。

## 产物与源文件

需求.md；待澄清与决策记录；初始追溯；本阶段验收规则、独立验收和确认。

MD 正文、结构化契约和任务各有单一权威来源，HTML从源生成。登记业务版本、来源版本、构建/代码快照和追溯入口。公共验收工具不代替业务产物生成或真实执行；由当前 Agent 使用环境可用工具完成。

## 自检与关卡

对照 `review-standard.md` 逐项检查，填写真实证据和未检查项；源缺失、证据不足或有阻塞不能判通过。再进入共享独立评审协议；修复后新轮次复验。默认人工阶段确认，已有明确预授权按真实依据登记。
