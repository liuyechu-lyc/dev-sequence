# 技术方案设计工作流

1. 检查工程原则与实际仓库，记录语言/运行时/依赖版本、平台、项目结构、性能和规模条件。空原则模板不能当作已批准原则。
2. 对阻塞未知项开展针对性研究或最小验证。记录证据、替代方案、取舍和 ADR，避免引入与需求无关的复杂架构。
3. 定义模块、数据流与故障边界，数据模型/生命周期、接口或事件的输入输出、授权、错误和恢复。按实际风险设计幂等、事务、并发、迁移、补偿和降级。
4. 设计部署配置、审计与可观测性、发布/停止/回退，非功能验证绑定已确认环境和负载。AI 产品补充权限、输出校验、接管、配置版本与评测，普通项目不启用。
5. 设计完成后复查工程原则；例外记录理由、较简单替代方案与真实批准依据，不通过单纯新增例外绕过原则。
6. 单独执行任务拆分：先基础依赖，再按可独立验证的用户价值切片。任务明确 ID、关联要求、产物/文件、依赖、完成条件、验证方法与必要风险。仅无依赖且无写冲突任务可并行。此步骤属于技术阶段的独立子步骤，不把粗架构段落冒充任务。
7. 对需求、原型、方案、契约和任务做一致性分析，检查遗漏/矛盾/歧义/无来源任务。结构工具只辅助查引用，语义检查要看原文；阻塞冲突先回写权威源。
8. 完成自检、独立方案评审和复验，确认技术取舍、实施范围和已接受风险。小修改可合并文档，但不能缺执行条件。

## 产物与源文件

技术方案.md及HTML；按需研究/ADR、数据模型、契约、运行验证说明；tasks.json与任务视图；一致性检查报告和方案确认。

MD 正文、结构化契约和任务各有单一权威来源，HTML从源生成。登记业务版本、来源版本、构建/代码快照和追溯入口。公共验收工具不代替业务产物生成或真实执行；由当前 Agent 使用环境可用工具完成。

## 自检与关卡

对照 `review-standard.md` 逐项检查，填写真实证据和未检查项；源缺失、证据不足或有阻塞不能判通过。再进入共享独立评审协议；修复后新轮次复验。默认人工阶段确认，已有明确预授权按真实依据登记。
