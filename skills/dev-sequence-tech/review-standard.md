# 技术方案设计验收规则

适用范围：本期已声明产物及其必要基线。保留项目特殊标准；不适用逐项说明理由。

| 检查ID | 验收标准 |
|---|---|
| TECH-01 | 基线及工程原则明确，需求/规则/AC 均映射到设计与验证；阻塞冲突已消除。 |
| TECH-02 | 架构职责、数据流、依赖和故障边界适合实际仓库，无无依据复杂度。 |
| TECH-03 | 关键未知有研究/验证，ADR 有证据、取舍及必要批准；数据/接口/事件契约可执行。 |
| TECH-04 | 按实际风险设计并发、幂等、一致性、权限、安全、外部依赖、迁移和恢复。 |
| TECH-05 | 性能、观测、配置、发布/回退及必要 AI 评测可落到验证任务。 |
| TECH-06 | 任务 ID、来源、具体产物、依赖、完成条件与验证方法齐全，依赖无环且可独立检验。 |
| TECH-07 | 需求/原型/方案/任务一致性检查完成，已知风险、方案确认和复用范围可追查。 |

## 共通通过条件

当前版本/指纹有效，清单逐项有实际证据，没有未解决或仅已修复未复验的阻塞问题。MD与HTML同源，原始报告不可覆盖。独立评审与用户阶段确认分开；正式豁免不显示全部通过。所有报告/请求/提示词存项目根验收记录目录。

## 项目补充规则

执行者据真实范围补充，不以模板默认条目代替本期检查清单；源规则变化须刷新受影响旧验收。
