# UI设计工作流

1. 建立参考清单。URL 实际访问并记录终端/时间；图片实际查看；HTML 连同依赖渲染；文件夹仅扫描指定范围。无法访问、缺依赖、字体或交互只能推断时明确标记。
2. 逐项记录采纳来源、用途、舍弃理由和冲突。多来源按布局/密度/颜色/组件分工，不机械拼接；不从截图推定业务规则。
3. 根据用户、场景和信息密度形成风格方向，给代表性页面。方向不明时提供少量实质差异方案，明确时直接推荐。先完成第一次「方向确认」。
4. 定义语义颜色、字体/行高、间距、圆角、阴影、网格、断点与密度；定义关键组件默认/悬停/聚焦/禁用/加载/错误状态。提供可见代表性页面，不只展示色板。
5. 检查声明终端上的可读性、对比度、键盘焦点和布局；对项目要求的无障碍等级记录具体验证。业务令牌与原型查看器 ds-* 框架令牌隔离。
6. 按本阶段规则独立验收后，完成第二次「规范版本确认」。确认绑定具体版本、预览和范围；无法由 Agent 代替用户判断的偏好保留用户决策，已有明确预授权按依据执行。
7. 后续原型/代码复用同一版本；风格变化更新源令牌并重建受影响产物，不假定内嵌 CSS 自动刷新。

## 产物与源文件

参考清单；风格方向与确认；tokens.css；设计规范.md及HTML；组件状态与代表性页面；规范版本与最终风格确认。

MD 正文、结构化契约和任务各有单一权威来源，HTML从源生成。登记业务版本、来源版本、构建/代码快照和追溯入口。公共验收工具不代替业务产物生成或真实执行；由当前 Agent 使用环境可用工具完成。

## 自检与关卡

对照 `review-standard.md` 逐项检查，填写真实证据和未检查项；源缺失、证据不足或有阻塞不能判通过。再进入共享独立评审协议；修复后新轮次复验。默认人工阶段确认，已有明确预授权按真实依据登记。
